## 1. Base Conventions

| Item | Value |
|---|---|
| Base URL (dev) | `https://api.orca-med.local/api/v1` (currently routed at `/api/...`; recommend version prefix) |
| Auth | Bearer access token (`Authorization: Bearer <access_token>`) issued by Sanctum + rotating refresh token |
| Token TTL | access `3600s`, refresh rotates with 7-day family expiry (`RefreshTokenService`) |
| Envelope (success) | `{ "success": true, "data": { ... } }` |
| Envelope (error) | `{ "success": false, "message": "...", "errors": {...} }` |
| Pagination | `paginate(20)`, Laravel `LengthAwarePaginator` shape (`data`, `links`, `meta`), supports `?page=` |
| Monetary types | decimal strings via `(string) $amount` — never floats |
| Status codes | `200` OK · `201` Created · `400` Validation · `401` Unauth · `403` Forbidden/inactive · `404` Not found · `422` Unprocessable |
| Rate limit (auth) | `throttle:10,1` on all `/auth/*` routes |
| Tenant scoping | Every resource query is forced by `participant_id` from the authenticated token; ownership mismatches → `403` + `SecurityAuditService::log('authorization_denied', ...)` |

Query filter keys (shared): `year` (2000–2200), `month` (1–12), `status`, `read` (boolean). Defined in `ParticipantCollectionRequest`.

## 2. Auth & Profile — ✅ Verified

### POST /auth/participant/login
Purpose: Authenticate partner/investor credentials.
Body:
```json
{ "username": "mahmoud_elmalawani", "password": "secret" }
```
Response `200`:
```json
{
  "success": true,
  "data": {
    "access_token": "...", "refresh_token": "...", "token_type": "Bearer", "expires_in": 3600,
    "user": { "id": 3, "username": "mahmoud_elmalawani" }
  }
}
```
Statuses: `401` invalid credentials · `403` inactive account.

### POST /auth/participant/refresh
Body: `{ "refresh_token": "..." }` → rotates token, same response shape. `401` invalid/expired.

### POST /auth/participant/logout · POST /auth/participant/password/change
- `logout` (auth) → revokes all tokens + rotates refresh family to dead. `200`.
- `password/change` (auth) Body: `{ "current_password", "password", "password_confirmation" }`. `422` wrong current password. On success: **revokes all sessions** (forces re-login).

### POST /auth/participant/password/reset/request · /password/reset
- `request` Body: `{ "email" }` → always `200` (anti-enumeration), writes 60-min token.
- `reset` Body: `{ "token", "password", "password_confirmation" }`. `400` invalid token.

### GET /me — ✅ Verified (`MeController@show`)
Profile for the header/avatar/settings entry.
```json
{
  "success": true,
  "data": {
    "id": 3, "username": "mahmoud_elmalawani", "name": "Mahmoud El Malawani",
    "email": "m@orca.med", "status": "active", "participation_start_date": "2023-01-15"

}
```

## 9. File Handlers & Receipts — ❌ GAP

### Signed upload/download for transfer receipts (التحقق من التحويلات)
`settlement_payments` currently lacks a file column. Proposed contract:

| Endpoint | Purpose / contract |
|---|---|
| `POST /me/settlements/{settlement}/payments/{payment}/receipt` | Multipart `file=` (PDF/PNG/JPG, ≤10MB). VALIDATE mime + size; store on private disk; persist `receipt_path` on payment |
| `GET /me/settlements/{settlement}/payments/{payment}/receipt` | Download; MUST be authenticated + ownership-scoped (payment belongs to participant's settlement item) |
| `GET /me/reports/{type}/download` | See §8 — prefer **signed temporary URL** (`Storage::temporaryUrl($path, 300)`) for large PDF/Excel instead of binary stream |

Rules:
- Store on private disk (`storage/app/private`), never `public`.
- Serve through controller that checks ownership of the parent settlement item before streaming.
- Generate signed URLs with expiry (300s) for share/download links.
- Record all download/upload events in `audit_logs` (`type='document_downloaded'`).
- Mime allowlist: `application/pdf, image/png, image/jpeg`; reject anything else (400).

## 10. Data Consistency & Calculation Rules

Every monetary value is immutable in storage; derived values are recomputed at read-time with `bc*` string arithmetic (reference: `GetParticipantDashboardDataAction` uses `bcsub` for `remaining`).

| Metric | Rule (source of truth) |
|---|---|
| `amount_due` (settlement) | `approved_profit_share + fund_share − previous_withdrawals` (settlement `amount_due`, per-item `profit_share` + `fund_share`) |
| `remaining` | `bcsub(amount_due, paid_amount, 2)` — computed, not stored |
| `movement` (capital growth) | `bcsub(current_snapshot_capital, previous_snapshot_capital, 2)` — sequential by `snapshot_date` |
| `participant_ratio` | `participant_capital_snapshot / CapitalSnapshot.total_capital` (decimal string, 8 d.p.) |
| `paid_amount` | SUM of `payments.amount` scoped to settlement |
| Fund allocation | one `ParticipantFundAllocation` per `participant_id+fund+monthlyProfit`; `allocation_type` ∈ {growth, incentive, depreciation} |

**Data consistency tests required:** sum(items.profit_share+fund_share) over a settlement == `amount_due`; `remaining == amount_due - paid_amount`; `fund_share` across a participant's allocations for a year matches yearly settlement `fund_share`.

## 11. Security & Multi-Tenancy (تنافذ البيانات)

1. **Everything** under `ensure.participant.context` requires a valid Bearer token; the guard type-checks `Participant` (403 otherwise).
2. Ownership enforcement pattern (reference `FinancialResourceController::authorizeOwner`): resource `participant_id` MUST equal token owner; mismatch → log to SecurityAuditService + **403**, never 404-first (prevents existence probing).
3. Auth routes rate-limited `10/min`; consider higher cap for file downloads and tighter cap on `/auth/*/login`.
4. Password change revokes **all** tokens + refresh family — keep this for mobile; do not "fix" it client-side.
5. Multi-tenant dashboard data must never join across participants: add assertions that `me/capital/growth` can only expose **company-level (non-PII)** aggregate rows (it currently returns company-wide snapshots — acceptable as market-wide data, confirm with product).
6. 2FA endpoints (once added) must require re-authentication (`password` or TOTP) on disable/revoke.

## 12. Performance & Caching Recommendations

| Data | Strategy |
|---|---|
| `GET /me` profile | Cache 5 min per participant (`participant:{id}:profile`) |
| KPI aggregates (`GET /me/kpis`, proposed) | Read-model / materialized summary from `capital_snapshots`; cache 24h, invalidate on new snapshot |
| `capital/growth` company series | Cache 1h; immutable snapshots → long TTL + tag invalidation |
| `funds`, `depreciation` (already-paginated) | `with('fund','monthlyProfit')` eager loading already used — keep; add `SELECT` column restriction |
| Notifications unread badge | Redis counter per participant, decrement on mark-read |
| Downloads | Streaming + signed URLs; never buffer full PDF in memory |
| Pagination | Keep default 20; add `per_page` cap (≤50) validation on all collection endpoints |
